# Расширение 1C-Битрикс 20.x сервиса «Экспресс Платежи: EPOS» 
<p>Расширение CMS 1C-Битрикс для интеграции с сервисом «Экспресс Платежи». Расширение позволяет автоматизировать прием платежей в системе EPOS.</p>

<a href="https://express-pay.by/extensions/1c-bitrix/epos">Инструкция для установки и настройки</a>

<a href="https://www.youtube.com/c/express-pay-by">Наш Youtube канал с опубликованными видео по расширениям</a>

Версия: 1.1.2

## Описание

Обработчик платежной системы для 1C-Битрикс 20.x (модуль sale), который выставляет счет в сервисе «Экспресс Платежи» для оплаты через E-POS и принимает уведомления об оплате в Битрикс.

В процессе оплаты обработчик:
- отправляет запрос на создание счета (web invoice) в API «Экспресс Платежи»;
- показывает покупателю страницу с инструкцией оплаты и QR-кодом;
- принимает подписанное уведомление (POST-параметры `Data` и `Signature`) и помечает оплату как выполненную при статусах `3` или `6`.

## Возможности

- Создание счета через API:
  - production: `https://api.express-pay.by/v1/web_invoices`
  - sandbox: `https://sandbox-api.express-pay.by/v1/web_invoices`
- Получение QR-кода для счета (base64) через API:
  - production: `https://api.express-pay.by/v1/qrcode/getqrcode/`
  - sandbox: `https://sandbox-api.express-pay.by/v1/qrcode/getqrcode/`
- Валюта: BYN (код валюты запроса `933`, список валют обработчика — `BYN`).
- Возврат пользователя после попытки оплаты:
  - `ReturnUrl` — `https://<server_name>` + путь текущей страницы + `result=success` и `ExpressPayAmount`
  - `FailUrl` — `https://<server_name>` + путь текущей страницы + `result=fail`
- Обработка уведомления об оплате:
  - ожидаются POST-параметры `Data` (JSON) и `Signature` (HMAC-SHA1);
  - подпись проверяется всегда, уведомления без подписи или с неверной подписью отклоняются;
  - номер счёта (`AccountNo`) и сумма из уведомления сверяются с платежом, уже оплаченный платёж повторно не проводится.
- Настройки, влияющие на возможность редактирования данных плательщиком в E-POS:
  - ФИО (`IsNameEditable`)
  - адрес (`IsAddressEditable`)
  - сумма (`IsAmountEditable`)
- Формирование статуса оплаты в Битрикс по данным уведомления:
  - при `Status = 6` статус описывается как «Оплачен с помощью банковской карты»
  - иначе используется описание «Оплачен»

## Требования

- 1C-Битрикс версии 20.x и выше с модулем «Интернет-магазин» (sale).
- PHP 7.1 и выше.
- Заполненное поле «URL сайта» (`server_name`) в настройках Главного модуля. Из него формируются адрес уведомлений и адреса возврата покупателя; если поле не заполнено, счёт не будет выставлен.
- Доступы/данные из личного кабинета «Экспресс Платежи»:
  - API-ключ (токен)
  - номер услуги (ServiceId)
  - секретное слово для подписи запросов
  - код в E-POS (ServiceCode)
  - секретное слово для подписи уведомлений
- Доступы/права и сеть:
  - исходящий доступ сервера к `api.express-pay.by` и `sandbox-api.express-pay.by`
  - публично доступный по https URL для приема уведомлений (см. настройку `EPOS_NOTIFICATION_URL`)

## Установка

Обработчик устанавливается вручную, без Маркетплейса. Код тот же, что и в модуле Маркетплейса `triincom.expresspayepos`.

1. Скопируйте папку `install/expresspay_epos/` из репозитория на сайт в каталог пользовательских обработчиков платёжных систем, сохранив имя папки `expresspay_epos`:
   - `/local/php_interface/include/sale_payment/expresspay_epos/` (рекомендуется)
   - или `/bitrix/php_interface/include/sale_payment/expresspay_epos/`

   В папке должны оказаться:
   - `.description.php`
   - `handler.php`
   - `lang/`
   - `template/`
2. Файлы обработчика в кодировке UTF-8. Если сайт работает в кодировке windows-1251, перекодируйте файлы из `lang/` и `template/lang/` в windows-1251.
3. Проверьте, что в настройках Главного модуля заполнено поле «URL сайта» (`server_name`).
4. В административной части откройте «Магазин → Настройки → Платёжные системы», добавьте платежную систему и выберите обработчик «Экспресс Платежи - E-POS» (`expresspay_epos`).
5. Заполните параметры обработчика (см. раздел «Настройка»).
6. Укажите в личном кабинете «Экспресс Платежи» адрес для уведомлений значением `EPOS_NOTIFICATION_URL` и включите цифровую подпись уведомлений с тем же секретным словом, что и в `EPOS_SECRET_WORD_FROM_NOTIFICATION`.

Проверка установки:
- в списке платежных систем доступен обработчик «Экспресс Платежи - E-POS»;
- при попытке оплаты по заказу открывается шаблон оплаты и отображается QR-код.

## Настройка

Настройка выполняется в параметрах платежной системы (обработчика) в админке 1C-Битрикс.

Поля конфигурации, которые используются обработчиком:

- `EPOS_IS_TEST_API` — работа в тестовом режиме (`Y/N`).
- `EPOS_TOKEN` — API-ключ (токен) доступа к API.
- `EPOS_SERVICE_ID` — номер услуги в сервисе «Экспресс Платежи».
- `EPOS_SERVICE_CODE` — код в E-POS.
- `EPOS_SECRET_WORD` — секретное слово для цифровой подписи запросов.
- `EPOS_NOTIFICATION_URL` — адрес для получения уведомлений. По умолчанию подставляется `https://<server_name>/bitrix/tools/sale_ps_result.php`; если «URL сайта» в Главном модуле не заполнен, поле остаётся пустым и его нужно заполнить вручную. Если сохранённый адрес указывает на другой домен, в настройках выводится предупреждение.
- `EPOS_IS_USE_SIGNATURE_FROM_NOTIFICATION` — использовать цифровую подпись при получении уведомлений (`Y/N`, по умолчанию `Y`). Подпись проверяется всегда, независимо от этой настройки; при значении `N` в настройках выводится предупреждение.
- `EPOS_SECRET_WORD_FROM_NOTIFICATION` — секретное слово для цифровой подписи уведомлений. **Обязательно**: без него уведомления об оплате отклоняются и оплата не засчитывается.
- `EPOS_IS_NAME_EDITABLE` — разрешено изменять ФИО плательщика (`Y/N`).
- `EPOS_IS_ADDRESS_EDITABLE` — разрешено изменять адрес плательщика (`Y/N`).
- `EPOS_IS_AMOUNT_EDITABLE` — разрешено изменять сумму оплаты (`Y/N`). Если плательщик изменит сумму, уведомление с суммой, не совпадающей с суммой платежа, будет отклонено.

Пример значений (без секретов):

- `EPOS_IS_TEST_API`: `Y`
- `EPOS_TOKEN`: `YOUR_TOKEN`
- `EPOS_SERVICE_ID`: `12345`
- `EPOS_SERVICE_CODE`: `1234567`
- `EPOS_SECRET_WORD`: `YOUR_SECRET_WORD`
- `EPOS_NOTIFICATION_URL`: `https://example.com/bitrix/tools/sale_ps_result.php`
- `EPOS_IS_USE_SIGNATURE_FROM_NOTIFICATION`: `Y`
- `EPOS_SECRET_WORD_FROM_NOTIFICATION`: `YOUR_NOTIFICATION_SECRET`
- `EPOS_IS_NAME_EDITABLE`: `N`
- `EPOS_IS_ADDRESS_EDITABLE`: `N`
- `EPOS_IS_AMOUNT_EDITABLE`: `N`

## Использование

Сценарий оплаты:

1. Покупатель оформляет заказ в 1C-Битрикс и выбирает способ оплаты «Экспресс Платежи - E-POS».
2. Битрикс вызывает обработчик, который отправляет запрос на создание счета в API (endpoint `web_invoices`).
3. Покупателю отображается страница оплаты:
   - выводится инструкция оплаты в E-POS;
   - выводится QR-код (получается через endpoint `qrcode/getqrcode`, `ViewType=base64`);
   - для оплаты также формируется «код» вида `<EPOS_SERVICE_CODE>-1-<ExpressPayAccountNumber>`.
4. Покупатель оплачивает счет в E-POS.
5. «Экспресс Платежи» отправляет уведомление на `EPOS_NOTIFICATION_URL` (обычно `/bitrix/tools/sale_ps_result.php`).
6. При получении `Data.CmdType = 3` и `Data.Status = 3` или `6` обработчик проверяет подпись, номер счёта и сумму и, если всё совпадает, помечает оплату как успешную.

Проверка оплаты:

- Тестовый режим:
  - включите `EPOS_IS_TEST_API = Y`, чтобы запросы выполнялись к `sandbox-api.express-pay.by`.
- Имитация webhook (проверка обработчика уведомлений):
  - отправьте POST на `EPOS_NOTIFICATION_URL` с параметрами `Data` (JSON-строка) и `Signature`;
  - используемые поля из `Data`: `CmdType`, `Status`, `AccountNo`, `Payer`, `Amount`;
  - `AccountNo` должен быть ID существующего неоплаченного платежа, а `Amount` — равен сумме этого платежа, иначе уведомление будет отклонено.

Пример `Data` (значения-заглушки):

```json
{
  "CmdType": 3,
  "Status": 3,
  "AccountNo": 100,
  "Payer": "Иванов И.И.",
  "Amount": "10.00"
}
```

`Signature` рассчитывается как `strtoupper(HMAC-SHA1(Data, EPOS_SECRET_WORD_FROM_NOTIFICATION))`, где `Data` — исходная JSON-строка уведомления.
